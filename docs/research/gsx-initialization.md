## Shared state and safeguards

GSX microphone and playback processing use the same model-specific object set:

`Global\CF4B411F-BE2B-4D84-8106-EC27CA0F8F05_1395_0098_{mutex,memory,event}`

B20 uses the separate `009f` set. GSX startup therefore accepts both complete microphone and playback settings in one explicit diagnostic input. The input is bound to the physical USB instance, not endpoint GUIDs or friendly names. Both active endpoints must be present, belong to that instance and be unambiguous among connected GSX units.

The helper validates the snapshot before opening native objects: schema, complete gate/filter/switch/microphone EQ, complete surround/playback EQ/reverb, compatible header/layout and agreement between typed settings and captured bytes. Unknown nonzero data beyond the recovered 2112-byte logical structure is refused rather than silently discarded. The 4096-byte mapped view and common native creation mechanism reuse the tested B20 implementation; the GSX experiment replays its own validated current capture rather than assuming B20 settings or seed-free defaults are suitable for GSX.

`--initialize-gsx` requires the vendor service to be stopped and holds a separate GSX initializer ownership lock. Existing complete objects, partial sets and creation races are refused without overwriting existing memory. New objects receive the captured GSX configuration and notify the processor. Health checks validate both pages and both connected endpoint identities. There is no repeated settings replay, reconnect policy, profile store mutation, driver installation, HID write or VST routing. GSX high-pass remains unsupported as an editable control; its captured state is preserved. Windows level/mute and USB sidetone are not part of the initialization snapshot and are not changed.

`--validate-gsx` validates the snapshot and physical endpoint pair without opening or creating vendor objects. Its `validated.json` explicitly reports no settings writes and no object creation; it never produces a fresh-initialization readiness claim.
