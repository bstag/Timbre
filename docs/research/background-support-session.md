# Background support preparation, 2026-10-09

The guided runner restores its starting baseline, while everyday shutdown must preserve the latest applied settings. The separate `SupportSession` interface provides start/cooperative stop/poll with real and demo adapters. Its elevated supervisor receives literal arguments, the caller's actual storage directory, selected device identities, a fresh report folder and controller PID/start instant. Startup/recovery pause edits; running enables normal controls. Guided checks and app-owned automatic replay are excluded while support is active, leaving existing saved-state opt-in policies to the hosts.

`SupportSessionPreparer` captures complete read-only buffers and validates device-matched typed seeds and saved records before service changes. No manually prepared diagnostic file is needed. The volatile `SessionSeedCache` preserves recent observed processing/unowned state for fresh reconnection without changing saves; opted-in saved state retains precedence. GSX is required at startup, and the currently connected B20 is included. A B20 absent at startup requires another explicit session.

`Start-SupportSession.ps1` excludes duplicate supervisors, requires recoverable EPOS support/Windows Audio and checks the original controller before takeover. It monitors managed hosts, vendor-service state, cooperative stop, controller liveness and a 24-hour deadline. Teardown snapshots latest controls/connected-device buffers, observes vendor ownership before requesting helper release, and verifies preservation. It never force-kills a host. Supervised duration options preserve the diagnostic 30..600-second bounds. Hosts attempt bounded `WindowsSessionRecovery` before disposing leases if the supervisor disappears, using the same existing-object inspector as PowerShell. This starts only vendor support and never restarts Windows Audio or writes DSP. Ordinary live handoff passed below; unexpected supervisor-loss recovery remains unvalidated.
