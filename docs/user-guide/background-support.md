# Background support session

This experimental source-checkout workflow supervises GSX processing and the B20 connected at startup while EPOS support is temporarily stopped. The installed EPOS driver/APO and recoverable vendor service remain required. Start it manually for this app session; it has a 24-hour maximum. Windows sign-in startup and service installation are not enabled.

Open **Background support · experimental** at the bottom of Connected devices. Connect one GSX microphone/sound pair and optionally one B20. Apply or discard pending edits, choose **Start support**, and handle administrator approval. Canceling approval leaves support unstarted. Startup pauses edits, captures fresh device-bound state and validates saved records before stopping EPOS support. Windows Audio keeps running. Source scripts and matching verified app/helper/test binaries are required; the portable ZIP excludes this infrastructure.

When support reports active, ordinary live/manual controls and explicit device/setup profiles remain available. Existing per-device saved-processing opt-in preferences govern connection restoration. Hosts retain recent observed processing in memory for fresh reconnection during this session; opted-in saved state takes precedence. Ordinary adjustments do not become named profile saves. A B20 absent at startup requires stopping support, connecting it and starting again.

Choose **Stop support** after applying/discarding pending edits. Keep connected devices connected during handoff. Timbre pauses edits, captures the latest applied controls, restarts EPOS support, observes vendor ownership before releasing hosts and checks exact preservation. It then verifies controls, complete buffers, services and vendor ownership repeatedly for at least one minute after helper release and Suite UI restoration. Keep the app and devices idle during this period. Shutdown preserves applied adjustments rather than undoing them to startup values. A detected competing change or lost interface fails verification; recovery does not blindly overwrite it. Profiles and setups remain explicitly saved; last-applied processing follows the app's existing persistence policy.

Closing Timbre requests recovery and delays closure until verified completion. Administrator startup approval or an active USB transaction must finish first. Recovery failure keeps the window available with reports. **Open reports** opens the session folder under `artifacts/support-session`.

The current full-buffer check is conservative: live capture or meter activity can change unowned data and fail verification while controls remain intact. Inspect the report rather than treating every buffer difference as a lost setting. The new sustained-handoff path is not yet validated for everyday use.

The supervisor watches the original Timbre PID/start instant, so unexpected app exit or PID reuse triggers recovery. Hosts also watch their supervisor and attempt bounded vendor ownership recovery while retaining leases if it disappears. Missing evidence, unavailable services, buffer differences or helper shutdown failures produce failure. This fallback does not establish recovery through power loss or Windows sign-out.

Offline/demo verification, real read-only preparation and short live Start/Stop and close-driven recovery sessions passed. Live pilots preserved applied B20 level/gate adjustments and a GSX playback EQ edit. Both devices passed physical reconnect while support was active, including fresh object creation and unchanged state on the other device. However, the B20 session's independent delayed shutdown check found GSX processing absent even though the old immediate summary passed. Sustained handoff with the new one-minute guard still needs a live pilot, and the underlying delayed-release cause is unresolved. Unexpected-exit recovery, cold boot and installed background lifecycle also remain separate work.
