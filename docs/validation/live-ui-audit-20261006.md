# Live controls and usability audit — 2026-10-06

Dated validation record. See [current validation status](status.md) for later results. Referenced artifacts are local evidence excluded from the repository.

The audit exercised the installed EPOS Control app on this PC with the physical **B20** and **GSX 300** connected and Gaming Suite running. It combined actual mouse/keyboard/accessibility interactions with independent reads through the existing native adapters. Hardware checks changed controls briefly and restored their starting settings. No audio recordings, service shutdown, driver replacement, unplug/replug or reboot was performed.

Evidence is under `artifacts/live-ui-audit-20261006`. Starting APO buffers are `artifacts/audit-b20-before.bin` and `audit-gsx-before.bin`; original user files were copied into the audit's `userdata-before` directory. These artifacts contain device identities and local settings and should remain outside distribution packages.

## Restoration and regression evidence

`mic-only-setup-isolation.json` verifies all endpoint level/mute values against the starting discovery. Sidetone restoration verifies the original channel values and mute. GSX's entire 4096-byte buffer matched the starting capture. B20's mapped control/configuration fields matched; differences were confined to float values at offsets 1088–1111, inside the recovered −120-initialized meter region. Their changes are consistent with runtime telemetry; the full B20 page is not claimed byte-identical. Those fields were not overwritten to force a match. See [initializer evidence](../research/apo-control-host.md) and the two `*-buffer-restoration.json` reports.

Original setup and processing-state files were restored byte-for-byte, and the audit-created device-profile file was removed because none existed at the start. File hashes were checked before reverting named profile/setup files to avoid replacing intervening edits. See `user-file-restoration.json`. Monitor capture was stopped before closing the app for the build.

The resulting source build passes **411/411 offline regressions and 94 WPF scenarios**, with no compiler warnings/errors. In the rebuilt live app, the GSX reason was visible with no gate/filter/EQ editors in its accessibility tree; returning to B20 recovered its actual controls and 50% gate. See `availability-fix-test-run.log` and `native-ui-fix-recheck.json`. Hardware checks and their restoration results are separate from the demo-based UI tests. `final-endpoint-restoration.json` confirms exact starting scalar levels and mute on all four endpoints, including restoration of the GSX's fractional level. `final-user-file-restoration.json` confirms the original files remained identical after reopening the app.

## Interface improvements, in priority order

1. **Make capabilities clear before editing or saving.** The stale processing editors are fixed. Next, mark GSX Microphone as unavailable for a complete setup snapshot before the user presses Save; keep basic gain/mute accessible. A future level-only snapshot must be an explicit choice, preserving complete saved snapshots when an adapter temporarily fails.
2. **Put the useful controls higher.** At the default 1100 × 780 window size, the device metadata, two setup checkboxes and status text consume most of the page; the microphone view is below the fold. Keep a compact device title, Sound/Microphone navigation and live/manual state at the top; move USB IDs, mix format, pickup status and restoration details into Device details.
3. **Keep monitoring and adjustment together.** A compact meter near gain and an optional graph beside gate/filter/EQ would let the user watch while adjusting. In the current vertical layout, opening the graph pushes processing controls out of view, limiting the usefulness of the hover guide. Keep measured dBFS separate from EQ gain and avoid presenting the gate guide as a measured threshold.
4. **Give setups enough room.** Replace the nested 300-pixel sidebar scroller with a dedicated setup editor or wider panel, keeping Save/Apply visible. Show a short scope summary such as “B20 microphone · GSX sound” and an explicit “B20 sound untouched.” The device list can also group Sound/Microphone under two physical devices rather than showing four nearly repeated names.
5. **Show availability and progress close to the action.** Use “Applying…”, “Applied”, “Draft” and inline errors with clear visual differences. The global footer can retain an old failed-save message while another feature works. Disable Apply profile when no profile is selected. Long setup names currently truncate in the narrow selector.
6. **Explain quiet capture and experimental status.** B20 samples updated below the chart's −90 dBFS lower grid, leaving an empty-looking plot despite successful capture. Show “Very quiet signal” plus a live-update indicator; retain readable fixed scales or offer an explicit expanded range. Show pickup pattern with a last-success timestamp in Device details, rather than alternating a prominent label between Cardioid and unavailable.

The next remote implementation work should address capability feedback and the compact layout. Listening, pickup-switch positions, unplug/replug and cold startup remain the next physical validation tasks. This audit makes no claim that those have passed.
