# Home validation checklist

Use the installed compatible EPOS driver/processor and keep Gaming Suite idle during app edits. Save a temporary device profile for each page you test, or a setup containing only those pages. Restore that snapshot after each test. Keep excluded pages unchecked so their settings stay untouched.

## Listening

For microphone gate/filter/EQ listening, use playback from a software mic test or a recording made from the selected EPOS Windows microphone endpoint. The app's Live activity graph analyzes capture but does not play it. Hardware sidetone uses a separately controlled monitoring path; hearing it alone does not establish that Windows capture EQ or filtering is applied. Keep mic level, speaking distance and the listening application's own processing unchanged during each comparison, and record which listening path was used.

Normal `Verify-Setup.cmd` checks package integrity, offline regressions, demo UI and device discovery. Optional switches in extracted 64-bit PowerShell:

```powershell
.\Verify-Setup.ps1 -HardwareGsxMicrophone
.\Verify-Setup.ps1 -HardwareGsxAudio
.\Verify-Setup.ps1 -HardwareGsxSidetone
.\Verify-Setup.ps1 -HardwarePlayback
.\Verify-Setup.ps1 -HardwareLoopback
.\Verify-Setup.ps1 -MonitorPackets 0098
```

Run one at a time. Microphone, sidetone and playback checks briefly change controls and report restoration; the sidetone check does not play/capture audio. Loopback plays a quiet two-second 1 kHz test tone and checks playback capture without changing settings. These checks do not certify audible monitoring/EQ/surround. Save the report path and record device, connection, driver version, starting profile, what you changed, expected result and observed result. A failed restoration needs attention before the next test.
